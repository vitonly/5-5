# Домен, хостинг в РФ и 152-ФЗ (гайд для СТАРТ+)

Документ для владельца платформы. **Это не юридическая консультация** — перед сбором и хранением персональных данных сверьтесь с юристом / специалистом по 152-ФЗ.

Сейчас сайт живёт на **Vercel** (фронт/API) + **Neon** (Postgres, часто EU/US) + **Vercel Blob** (файлы) + **Telegram Bot API**.

---

## 1. Покупка домена

### Что купить
- Для аудитории РФ удобны зоны **`.ru`** / **`.рф`**.
- Регистраторы: [REG.RU](https://www.reg.ru), [Timeweb](https://timeweb.com), [Beget](https://beget.com), [Ru-Center](https://www.nic.ru) и др.

### Шаги
1. Проверить занятость имени.
2. Зарегистрировать на **себя / ИП / ООО** (данные WHOIS — как требует регистратор).
3. Включить **автопродление** и подтвердить email.
4. В панели DNS создать записи на хостинг (см. ниже).
5. Выпустить **SSL** (Let’s Encrypt на хостинге или Cloudflare).

### DNS (типично)
| Тип | Имя | Значение |
|-----|-----|----------|
| A | `@` | IP сервера |
| A / CNAME | `www` | IP или `@` |
| CNAME | (если PaaS) | адрес провайдера |

TTL можно 300–3600 сек на время переезда.

## 2. Хостинг в РФ (ориентиры)

Нужно разместить:
- **Next.js** (Node 20+)
- **PostgreSQL**
- **файлы** (сейчас Blob) — S3-совместимое хранилище в РФ или диск сервера
- **cron** (просрочки домашек, дедлайны сезонов)
- **env-секреты** (Telegram, БД, session)

### Варианты (примеры)
| Площадка | Плюсы | Минусы |
|----------|--------|--------|
| **Timeweb / Beget / REG.RU VPS** | Просто, РФ, дешево | Сами обновляете Node, nginx, SSL |
| **Selectel / Yandex Cloud** | Масштаб, S3 в РФ, managed Postgres | Сложнее и дороже |
| **Vercel + Neon** (как сейчас) | Удобный деплой | Инфра часто **вне РФ** |

Для «серверы в РФ» обычно: **VPS или облако РФ** + **Postgres в РФ** + **объектное хранилище в РФ**.

### Минимальный стек на VPS
1. Ubuntu LTS, firewall (22, 80, 443).
2. Node.js LTS, `pnpm`/`npm`, PM2 или systemd.
3. Nginx reverse proxy → `localhost:3000`, SSL (certbot).
4. Postgres (локально или managed в РФ).
5. Папка `/uploads` или S3 (Yandex Object Storage / Selectel).
6. Cron: `curl` на `/api/cron/automation` с заголовком `CRON_SECRET` (как на Vercel).

Сборка:
```bash
npm ci
npx prisma generate
npx prisma db push   # или migrate deploy
npm run build
NODE_ENV=production npm start
```

Перенести **все** переменные из Vercel (Telegram, `DATABASE_URL`, `BLOB_…` или новый upload backend, `ADMIN_TELEGRAM_IDS`, `NEXT_PUBLIC_APP_URL`, session secret, `CRON_SECRET`).

Обновить **Telegram webhook** на новый домен (`/api/telegram/webhook`).

## 3. Перенос с Vercel (чек-лист)

1. Купить домен + VPS/облако в РФ.
2. Поднять Postgres, сделать **dump Neon** → restore.
3. Настроить upload (диск или S3 РФ), проверить аватары/домашки/чат-фото.
4. Задеплоить Next, проверить логин через Telegram.
5. Переключить DNS, дождаться пропагации.
6. Обновить webhook бота и `NEXT_PUBLIC_APP_URL`.
7. Включить cron на сервере.
8. Оставить Vercel на 1–2 недели как fallback, потом выключить.

## 4. 152-ФЗ: что учесть (обзор)

### Какие данные уже есть на платформе
- Telegram ID / chat ID, имя, username
- Фото профиля, вложения домашек, фото в чате
- Оценки силы/тильта, дневник прогресса, очки, посещаемость
- Сессии логина (cookies)

Это **персональные данные** (и частично спецкатегории не относятся, но биометрия лица с фото — спорная зона; храните минимум).

### Кто оператор
Лицо (ИП/ООО/физлицо), которое определяет цели обработки. Оператор отвечает за согласие, политику, безопасность, при необходимости — **уведомление Роскомнадзора**.

### Что сделать на практике (чеклист)
1. **Политика конфиденциальности** на сайте (отдельная страница) + ссылка в футере / при входе.
2. **Согласие на обработку ПД** при первом входе / привязке Telegram (чекбокс + текст).
3. **Цели обработки** прозрачно: обучение, 5v5, рейтинг, связь с тренером.
4. **Минимизация**: не просить лишнего; удалять ненужные файлы.
5. **Срок хранения** и процедура удаления по запросу ученика.
6. **Доступ**: только тренер (ADMIN) и сам ученик; логи действий желательно.
7. **Хранение в РФ**: если требуется для вашей модели (часто — для граждан РФ и локальных операторов) — БД и файлы на инфраструктуре в РФ.
8. **Передача за рубеж** (Vercel/Neon вне РФ): отдельное основание / согласие / договор с оговорками — это главный риск текущего стека.
9. **Cookies / сессии**: кратко указать в политике.
10. При достижении критериев закона — **уведомление Роскомнадзора** о начале обработки (уточнить у юриста).

### Рекомендация по продукту
- Добавить страницы `/privacy` и согласие при логине (отдельная задача после переезда или до него).
- Не слать в Telegram лишние ПД третьих лиц без нужды.

## 5. Краткие рекомендации «что купить»

1. Домен `.ru` у REG.RU / Timeweb.  
2. VPS 2 vCPU / 4 GB RAM в РФ + managed Postgres в РФ **или** один VPS с Postgres.  
3. Object Storage в РФ для фото/демо.  
4. Бюджет заложить на SSL (обычно бесплатно) + бэкапы БД ежедневно.

После покупки можно вернуться к разработке: поможем с конфигом Nginx, env и переносом Prisma.
