# Модуль Б: проверка и выкладка

## Совместимость

Старые ID уроков `b-l0`…`b-l10`, четырёх тетрадей `b-clean`, `b-calc`, `b-charts`, `b-pres` и семи вариантов сохраняются. Функция `reviewB` и `BTrainer` не изменены: прежние ответы разбираются прежними правилами. В меню основной маршрут — четыре задания, прежние объяснения доступны рядом и в архиве.

Новые попытки `b-practice-*` используют отдельные данные: `_b_seed`, `_b_mode`, `_b_focus`. Данные и ключи — единый генератор версии 1 в `b-dataset.ts`. При дальнейшем изменении генератора нужна новая версия: нельзя менять смысл seed ранее созданных попыток. Сданный разбор `_b_report` фиксируется сервером. Служебные поля недоступны для изменения учеником.

«Повторить ошибки» создаёт новый набор данных для навыков, на которых ошиблись в прежней работе; учитываются также замечания наставника после оценки. Просмотр разбора до сдачи отмечается сервером, поэтому исправленный после просмотра ответ не считается самостоятельным.

## Границы проверки

- Ответы в тетради проверяются по данным конкретного варианта, включая поля сравнения, решение по записи, настройки сводных, агрегаты, топ-5 и ссылку на исходные данные.
- Длина журнала и цифра в тексте не дают успешной оценки.
- Office-проверка читает структуру XLSX/PPTX: листы, сводные, типы диаграмм, число слайдов, размер 16:9. Наличие XML-частей не доказывает правильность, видимость или читаемость графиков и сводных. Эти пункты явно передаются наставнику.
- Нельзя автоматически подтвердить охрану труда, перерывы и физическую флешку. Б4.1 и Б4.2 оцениваются отдельно в форме наставника по наблюдению.
- Конкурсные баллы выставляются только в существующей ведомости: 6 + 6 + 7 + 1 = 20. Учебные проверки не добавляют к ней баллы.

## Проведённые проверки

Локальная итоговая сборка и TypeScript прошли. Все 36 автотестов проходят; ESLint — 0 ошибок, 13 прежних предупреждений. Для ESLint исключён локальный приватный экспорт `claude-import/**`, который не относится к исходникам сайта.

Изолированная локальная PostgreSQL-совместимая база PGlite; тестовый ученик, наставник, другой ученик и пользователь без доступа. Реальные данные сайта не изменялись, Telegram отключён тестовым токеном.

1. Браузер: урок → практика → сохранение → перезагрузка → сдача → разбор → повтор на новых данных.
2. Прежняя тетрадь «Осеннего кубка»: прежний ответ, ссылка на исходный XLSX, исходный разбор. Проверена локальная старая попытка; у найденной на сервере учётной записи Ярослава сохранённых попыток Б не оказалось.
3. Новый вариант и ответы сохраняются; мгновенную перезагрузку страхует локальный черновик. Серверные сохранения идут по очереди, есть явная кнопка сохранения и сообщение об ошибке.
4. API: отсутствие входа, отсутствие доступа, чужие попытки, подмена seed/режима/разбора, изменение после сдачи, повтор ошибок другой работы.
5. Загрузка настоящих ZIP-пакетов XLSX/PPTX, проверка 5/6 слайдов и 16:9/4:3, отсутствие сводных/диаграмм, сброс устаревшей проверки после замены файла. Данные ячеек не копируются в большой JSON отчёта; размер отчёта ограничен.
6. Официальный прогон: отсутствие исходника блокирует старт; при наличии снимок вложения сохраняется. Первый этап 240 минут, перерыв не расходует время второго, второй этап 120 минут; между днями сохранение запрещено.
7. Наставник видит историю самостоятельных ответов на разных вариантах и факт просмотра разбора. Существующая форма оценки сохраняет оценки без дублирования баллов.
8. На опубликованном сайте выполнена только проверка чтением: приложение 9 видно под ролью ученика и скачивается с HTTP 200. Старое вложение `b-chempionat` используется новым официальным прогоном, повторная загрузка не нужна.

Проверка в настольном Excel/PowerPoint и весь новый маршрут на production ещё не выполнялись. Новые страницы можно проверить на production после согласованной выкладки.

## План выкладки

Ветка `codex/module-b-practice`. Основной скрипт — `python scripts/vps_release.py`: сначала `--dry-run`, затем обычный запуск после согласия владельца. Список файлов берётся из dry-run по зафиксированному коммиту.

Схема Prisma, зависимости npm, серверный `.env` и nginx не меняются. Дополнительный `db push` не нужен: новые данные хранятся в существующей тетради попытки. Скрипт собирает новый релиз, переключает ссылку и перезапускает pm2; при неуспешной проверке доступен откат релиза.

После выкладки: проверить `/poligon/b`, урок, новую попытку, сохранение/перезагрузку, загрузки и разбор; наставнику — `/admin/poligon`, форму оценки и историю практики Б. Проверить опубликованное приложение 9 под ролью ученика, страницу старой попытки (если она появится) и свежие логи pm2. Только после успешной проверки — слияние в master и push по согласованию.
